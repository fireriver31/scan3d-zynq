# PYNQ integration checks

先核对当前Notebook格、输入数据及软硬件版本。把实体屏、DDR原始帧、Notebook输出和保存文件分别观察；不要用其中一层的正常替代其他层验证。

## 根据故障选择检查

- Overlay、IP访问异常：运行`scripts/overlay_audit.py`检查明确提供的bit/hwh。该脚本只读本地文件，不会下载bit、访问板卡或证明硬件已加载。名称、器件、版本一致只是元数据检查；还需比较发布指纹，并通过工程已有状态接口核对实际加载内容。
- 寄存器访问报找不到`read`：结合该版本HWH的地址范围核对对象类型。旧PYNQ可能把module-reference解析成Hierarchy；只有地址和接口已核实后才能用相应MMIO驱动，不能把任何Hierarchy都当寄存器IP，也不能猜地址。
- DMA或数据不一致：按`references/workflow.md`核对所有权、长度、缓存和布局。发送的源数组、DMA完成后数据和离线参考必须关联同一输入。延时长先分开计时PS准备、传输/等待、后处理和存档，不按进度栏标题判断瓶颈。
- 实际PL与参考对照：用`scripts/compare_arrays.py`显式选择字段，保留dtype、shape和原始数值。参考算法应独立推导；两段共用同一错误取样公式的程序一致，不等于公式正确。

## 验证约束

使用工程已授权的加载和运行入口，不为只读核查额外重载Overlay。对PL持续写固定DDR的工程，加载前须通过本次启动状态确认地址已保留；本案例地址仅是案例，不是通用配置。

DMA的flush/invalidate、发送接收启动顺序和等待条件必须服从实际PYNQ版本、DMA模式及IP接口约定。先确认这些条件，再改代码；不要把一种IP的协议写成所有DMA通用规则。

位宽转换先使用独立递增图案核验打包/展开顺序，区分空间像素次序、RGB通道顺序和字节序，不根据照片色偏随意反转字节。硬件所有权或完成状态未确认时，不释放仍可能被PL访问的缓存。

记录结果属于仿真、主机重放还是板上实测，并明确其覆盖范围。没有板测的脚本不能写成已在任意板卡验证；没有体积真值的逐位一致也不能称测量精度通过。

具体案例、命令和失效条件见`README.md`与`references/workflow.md`。只有涉及该项目的历史原因时读取`references/cases.md`。

复用其他题目时由调用者指定IP名、字段和文件，不要求recon_0或扫描工程。离线跨设备元数据/跨任务验证见`tests/validate_reuse.py`；这些是合成夹具，不等于真实跨板上机。普通技能包的可复用要求与通用PYNQ加分应分别陈述。

需要整理输入约定、设计可核查的提问或给另一项目留下排查记录时，读取[复用工作表](references/reuse_worksheet.md)。先选与故障相关的一行；未知IP、地址或布局须留空，不将案例参数当作目标工程配置。
