# 从真实失败提炼的案例

## 1. Hierarchy不是寄存器IP

旧PYNQ把自定义module-reference呈现为Hierarchy，直接调用read时报“找不到read”。核实HWH地址后使用实际MMIO接口，并保留硬件标识校验。经验是先分清对象类型和接口，不能看到属性名就认为是可读写IP。

## 2. 两个程序对同一错误数组一致

16→64bit写FIFO与64→16bit显示FIFO采用高位先行，PS小端uint16直接reshape造成每4像素次序反转。PL和Python对同一错序照片逐位一致仍未发现空间布局错误。独立递增序列及实际FIFO实现才揭示问题。复用的是核验方法，不能把“每4像素反转”硬编码到其他工程。

## 3. 标称时钟和实际时钟不同

该工程要求50MHz，板上读回为46.875MHz；修正后板上读回50.0MHz，独立UI边框正常。HWH标称源与运行PS源不一致时，只看名义频率不够。读回方法要适配目标PYNQ版本，50MHz仅为本案例要求。

## 4. 看似PL慢，实际耗时在PS

一份板上旧日志总耗时约907秒，288次DMA等待合计约3.888秒；其他时间包含PS区域统计和压缩存档。不能按界面“PL掩模处理”认定FPGA一直算十几分钟，也不能把包含关系的计时重复相加。

## 5. 逐位一致与测量精度不同

同圈288次保存的实际PL位与整数模型0差异，证明该部分计算与配置吻合；后处理仍可能漏部件，体素外形仍可能断裂。物理精度必须另有参考测量，不能由同输入一致推导出来。

相关日志、数组和工程排错过程见[实验记录](../../../report/system_design.md)，板上输入与数字参考见[实测资料](../../../data/README.md)。本页概括可复用的检查方法，具体命令见README和workflow。

## 6. 单次实物参考如何补充数字验证

近似长方体用直尺测得12.2×9.2×5.4cm，参考606.096cm³；一次严格占据测量637.328cm³，偏差5.153%。它补充了独立于系统体素计数的物理尺寸参考。量具分辨率、重复性和形状误差仍需分别登记，不能把脚本复算一致当成所有精度指标通过。完整条件见[本次实验](../../../report/board_volume_experiment.md)。
